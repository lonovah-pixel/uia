# Такси всё в одном

Одно приложение вместо шести: указываете, откуда и куда едете, и сразу видите цены
**Яндекс Go, Uber, Ситимобил, Такси Максим, inDrive и Wheely**. Приложение выделяет
самый выгодный тариф, а заказ открывается в один тап в приложении выбранного сервиса.

- 📍 Адрес подачи определяется автоматически, точки можно найти поиском или отметить на карте (маркеры перетаскиваются).
- 🏆 **Самый выгодный вариант** — не только самый дешёвый: учитывается и время подачи (настраивается, сколько стоит минута ожидания).
- 🏷 Бейджи «Дешевле всех», «Быстрее всех», индикатор повышенного спроса ⚡.
- 🚕 Фильтры по классу (Эконом, Комфорт, Комфорт+, Бизнес, Минивэн) и сортировка: выгоднее / дешевле / быстрее.
- 💸 «Экономия до N ₽» по сравнению с другими сервисами того же класса.
- 🔄 Цены обновляются каждую минуту.
- 📱 PWA: устанавливается на телефон как приложение, светлая и тёмная тема, работает на iOS, Android и десктопе.

## Откуда берутся цены

У большинства агрегаторов нет открытого API цен, поэтому приложение работает в двух режимах
и честно показывает, какой из них используется:

| Режим | Как получается | Как выглядит в приложении |
| --- | --- | --- |
| **Цена сервиса** | Запрос в официальное API агрегатора. Сейчас поддерживаются **Яндекс Go** (партнёрское API `taxi_info`) и **Uber** (Riders API). Нужны ключи. | `350 ₽` · «цена сервиса» |
| **Оценка** | Расчёт по модели тарифа: подача + км + минуты, минимальная стоимость, множитель города, коэффициент спроса по времени суток и дню недели, пробки. | `≈ 340–410 ₽` · «оценка» |

Если API агрегатора не ответило, для него автоматически показывается оценка и предупреждение.
Тарифы для оценок — ориентировочные московские цены в `packages/core/src/providers.ts`
(для других городов действуют множители из `packages/core/src/cities.ts`). Их стоит
периодически сверять с реальными тарифами.

Заказ открывается по диплинку в приложении агрегатора. Для Яндекс Go и Uber маршрут
подставляется автоматически, для остальных открывается сайт или приложение сервиса,
и маршрут нужно ввести там: публичных диплинков с маршрутом у них нет.

## Быстрый старт

Нужен Node.js 22.12 или новее.

```bash
npm install
npm run dev          # API на :3000 и фронтенд на http://localhost:5173
```

Продакшен (один процесс отдаёт и API, и фронтенд):

```bash
npm run build
npm start            # http://localhost:3000
```

Или в Docker:

```bash
docker build -t taxi-all-in-one .
docker run -p 3000:3000 --env-file .env taxi-all-in-one
```

Проверки:

```bash
npm run check        # типы + тесты (core и server)
```

## Настройка

Скопируйте `.env.example` в `.env`. Все переменные необязательны:

| Переменная | Назначение |
| --- | --- |
| `YANDEX_TAXI_CLID`, `YANDEX_TAXI_APIKEY` | Реальные цены Яндекс Go. Ключи выдаются после подключения к партнёрской программе Яндекс Go. |
| `UBER_ACCESS_TOKEN` | Реальные цены Uber (Riders API, доступ к estimates). |
| `OSRM_URL` | Роутер для расчёта маршрута по дорогам. По умолчанию — публичный демо-сервер OSRM; для продакшена поднимите свой. Пусто — оценка по прямой. |
| `PHOTON_URL` | Геокодер (поиск адресов) на данных OpenStreetMap. Для нагрузки — свой экземпляр Photon. |
| `HTTP_TIMEOUT_MS` | Таймаут запросов к внешним API (по умолчанию 4000). |
| `PORT`, `HOST` | Адрес сервера. |

## Устройство

```
packages/core   Общая логика (используется и сервером, и фронтендом):
                каталог агрегаторов и тарифов, профили городов, модель спроса и пробок,
                оценка цены, ранжирование и выбор лучшего варианта, диплинки, форматирование
apps/server     API на Fastify: опрос агрегаторов параллельно с таймаутами, адаптеры к
                реальным API (Яндекс Go, Uber), маршрут (OSRM), геокодер (Photon), кэш,
                ограничение частоты запросов; в продакшене раздаёт собранный фронтенд
apps/web        React + Vite + Leaflet, мобильный интерфейс, PWA
```

Как формируется ответ на запрос цен:

1. По точке подачи определяется город: от него зависят множитель цены, загруженность дорог и часовой пояс.
2. Строится маршрут (OSRM или оценка по прямой), время в пути увеличивается с учётом пробок в это время суток.
3. Все агрегаторы опрашиваются параллельно: где есть ключи, через их API, иначе по модели тарифа.
4. Предложения ранжируются: `score = цена + время подачи × стоимость минуты`. Минимальный score получает бейдж «Самый выгодный».

### API

| Метод | Описание |
| --- | --- |
| `POST /api/quotes` | Тело: `{ from: {lat, lon, name?}, to: {...}, when?, tzOffsetMin?, providers?, classes?, valueOfTimePerMin? }`. Ответ: маршрут, город, предложения с бейджами, сводка (`bestId`, `cheapestId`, `fastestId`), статусы агрегаторов, предупреждения. |
| `GET /api/providers` | Список агрегаторов, их классы и подключено ли API. |
| `GET /api/geocode?q=&lat=&lon=` | Подсказки адресов (с приоритетом точек рядом с `lat`/`lon`). |
| `GET /api/reverse?lat=&lon=` | Адрес по координатам. |
| `GET /api/health` | Проверка работоспособности. |

### Как добавить агрегатор

1. Добавьте запись в `PROVIDERS` (`packages/core/src/providers.ts`): название, цвета логотипа, тарифы и функцию `deepLink`.
2. Если у агрегатора есть API цен, напишите адаптер по образцу `apps/server/src/adapters/yandex.ts`
   и зарегистрируйте его в `apps/server/src/adapters/index.ts`. Без адаптера будут показываться оценки.
3. Добавьте тесты. Тесты каталога автоматически проверят уникальность кодов тарифов и корректность диплинков.

Новый город добавляется в `CITIES` (`packages/core/src/cities.ts`): центр, радиус, множитель цены, загруженность дорог и часовой пояс.

## Ограничения

- Точные цены доступны только по подключённым API. Остальное — оценка, и итоговую сумму покажет приложение сервиса при заказе.
- Заказать поездку прямо из приложения нельзя: публичных API заказа у агрегаторов нет. Заказ открывается в их приложениях.
- Публичные OSRM и Photon предназначены для демонстрации. Для реальной нагрузки разверните свои экземпляры.
- Состав сервисов и их тарифы различаются по городам. Ненужные сервисы можно отключить в настройках приложения.
